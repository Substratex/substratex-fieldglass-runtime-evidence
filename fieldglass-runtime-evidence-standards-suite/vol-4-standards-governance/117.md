# Abstract

The Runtime Investigation Routing Standard (RIRS™) defines how Runtime Evidence systems guide operators through reconstructed evidence.

The standard establishes a formal mechanism for:

* Runtime investigation classification
* Evidence prioritization
* Guided reconstruction
* Investigation routing
* Investigator assistance
* Runtime evidence navigation

RIRS™ exists because evidence generation alone does not guarantee evidence understanding.

The standard provides a structured pathway from runtime reconstruction to human investigation.

---

# Purpose

Modern Runtime Evidence systems may generate hundreds of telemetry signals, evidence objects, timelines, replay artifacts, and investigative surfaces.

Without guidance, operators frequently encounter a fundamental problem:

> Where should I inspect first?

RIRS™ solves this problem through evidence-driven routing.

The standard enables Runtime Evidence platforms to recommend investigation pathways based on the evidence contained within a reconstructed run.

# Investigation Classification Layer

A Runtime Evidence system shall classify each reconstructed run into one or more investigation categories.

## Stable Run

Definition:

```text
No significant instability observed.
No boundary crossing observed.
No observable failure observed.
```

Purpose:

```text
Validation
Review
Export
```

---

## Temporal Formation

Definition:

```text
Warning onset precedes visible failure.
Lead-time evidence present.
Temporal pressure observable.
```

Primary Question:

> When did failure begin forming?

---

## Boundary Failure

Definition:

```text
Containment weakened.
Basin Exit observed.
Recovery absent or weak.
```

Primary Question:

> When did the system leave recoverable bounds?

---

## Role Breakdown

Definition:

```text
Role fragmentation elevated.
Authority clarity weakened.
Handoff integrity degraded.
```

Primary Question:

> Did coordination contribute to instability?

---

## Runtime Drift

Definition:

```text
Instability spread through the run.
Continuity weakened.
Repeated pressure accumulated.
```

Primary Question:

> How did instability propagate?

---

## Pressure Event

Definition:

```text
Runtime pressure elevated.
Recovery reserve depleted.
Structural cost increased.
```

Primary Question:

> What cost accumulated during execution?

---

## Emergence Event

Definition:

```text
Recurrence patterns present.
Continuation signatures present.
Re-entry evidence observed.
```

Primary Question:

> What higher-order runtime structure appeared?

---

## Multi-Factor Incident

Definition:

```text
Multiple high-priority investigative domains active.
```

Primary Question:

> How did multiple evidence layers interact?

# Chief Investigator Layer

RIRS™ defines an optional Chief Investigator layer.

Purpose:

```text
Explain where to inspect.
Not what to conclude.
```

Example:

```text
Chief Investigator

This run appears to be a
Boundary Formation Incident.

Suggested Path

Evidence State
↓
Failure Timeline
↓
Failure Boundary
↓
Runtime Replay
↓
Export
```

The Chief Investigator shall remain advisory.

It shall not generate final conclusions.

# Claim Boundaries

RIRS™ does not:

* infer hidden state
* infer consciousness
* infer intent
* assign blame
* determine truth
* establish legal liability
* determine root cause certainty
* replace human review

RIRS™ provides investigation guidance derived from Runtime Evidence.

---

# Conformance

A Runtime Evidence platform conforms to RIRS™ if it:

1. Implements investigation classification.
2. Produces an Investigation Guide Object.
3. Supports evidence-driven routing.
4. Exposes primary investigation pathways.
5. Preserves investigation guidance in exported evidence artifacts.
6. Maintains claim-boundary compliance.

---

# Summary

The Runtime Investigation Routing Standard transforms Runtime Evidence from a collection of evidence surfaces into a guided investigative workflow.

The objective is not merely to display evidence.

The objective is to help operators understand where evidence should be inspected, challenged, reviewed, and preserved.

RIRS™ represents the transition from Runtime Evidence generation to Runtime Evidence investigation.
