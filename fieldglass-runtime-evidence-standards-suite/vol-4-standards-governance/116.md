# Abstract

Not all runtime metrics represent the same kind of claim.

Some metrics are directly observable.

Some are deterministically derived.

Some are bounded proxies.

Some are interpretive research layers.

Some remain experimental.

The Metric Legitimacy Matrix (MLM) establishes a canonical framework for classifying runtime metrics according to:

* Evidence basis
* Certification scope
* Challengeability
* Claim boundaries
* Artifact inclusion rules

The MLM serves as the epistemic trust layer of the Runtime Evidence™ ecosystem.

Its purpose is to ensure that every public metric discloses:

1. What kind of evidence it represents.
2. Where it originates.
3. How it is computed.
4. Whether it is challengeable.
5. What it is permitted to claim.
6. What it is explicitly prohibited from claiming.

---

# 1. Purpose

Fieldglass® does not treat all metrics as equivalent.

A metric such as:

```text
Turn Count
```

is fundamentally different from:

```text
Runtime Pressure
```

which is fundamentally different from:

```text
Emergence Dynamics
```

The MLM formalizes these distinctions.

---

# 2. Core Principle

Every public metric MUST belong to a legitimacy class.

No metric should be presented without disclosure of:

* Evidence Class
* Certification Scope
* Challengeability
* Claim Boundary

---

# 3. Legitimacy Classes

## Class 1 — Direct Evidence

### Definition

Directly parsed, counted, extracted, or located from acquired runtime evidence.

### Characteristics

* Observable
* Deterministic
* Reproducible
* Fully challengeable

### Certification

Certified

### Examples

* Turn Count
* Role Count
* Tool Failure Count
* Explicit Failure Markers
* Runtime Event Count

---

## Class 2 — Derived Evidence

### Definition

Deterministically computed from direct evidence using disclosed rules.

### Characteristics

* Traceable
* Recomputable
* Replayable

### Certification

Certified

### Examples

* Lead-Time
* Replayability
* Evidence Integrity
* Formation Timeline
* Boundary Crossing

---

## Class 3 — Proxy Signal

### Definition

Observable but heuristic runtime indicators derived from evidence patterns.

### Characteristics

* Traceable
* Bounded
* Partially challengeable

### Certification

Certified with explicit boundaries

### Examples

* Runtime Drift
* Runtime Pressure
* Role Topology
* Containment Coupling
* Basin Pressure

---

## Class 4 — Interpretive Layer

### Definition

Research interpretation over observed runtime evidence.

### Characteristics

* Contextual
* Research-oriented
* Not certified as fact

### Certification

Preserved for review

Not certified as hidden-state truth.

### Examples

* Emergence Dynamics
* Symbolic Time
* Continuity Interpretation
* Re-Entry Interpretation

---

## Class 5 — Experimental

### Definition

Signals requiring additional validation and independent review.

### Characteristics

* Research-only
* Subject to revision
* Not certified

### Certification

Not certified

### Examples

* Early-stage research metrics
* Candidate observables
* Validation studies

---

## Class 6 — Governance Artifact

### Definition

Metrics describing evidence integrity, provenance, replayability, preservation status, and certification state.

### Characteristics

* Evidence governance
* Preservation-oriented
* Non-behavioral

### Certification

Certified

### Examples

* Evidence Integrity
* Replayability
* Provenance Completeness
* Certification State
* Evidence Chain Status

---

# 4. Challengeability Model

Every public metric MUST disclose challengeability.

## Yes

Directly challengeable through evidence inspection or deterministic recomputation.

Examples:

* Turn Count
* Lead-Time
* Evidence Integrity

---

## Partial

Depends on bounded heuristics but exposes source signals.

Examples:

* Runtime Drift
* Runtime Pressure
* Role Topology

---

## Experimental

Requires additional validation and research review.

Examples:

* Emergence Dynamics
* Symbolic Time

---

## Prohibited

Public metrics SHOULD NOT use:

```text
Challengeability = No
```

If a metric cannot be challenged, it SHOULD NOT be presented as a public runtime metric.

---

# 5. Certification Scope

Certification does NOT mean:

* Truthfulness
* Correctness
* Benchmark superiority
* Deployment approval
* Hidden-state access
* Consciousness detection
* Intent inference
* Root-cause certainty

Certification means:

1. Runtime evidence was acquired.
2. Runtime evidence was computed.
3. Telemetry was generated.
4. An artifact was produced.
5. Provenance metadata exists.
6. The evidence chain is replayable.
7. The artifact is preservable.

---

# 6. Certification Inclusion Rules

## Included

* Direct Evidence
* Derived Evidence
* Bounded Proxy Signals
* Governance Artifacts

## Preserved But Not Certified

* Interpretive Layers
* Experimental Signals

---

# 11. Claim Boundaries

The MLM exists to prevent category errors.

A proxy signal is not a fact.

An interpretive layer is not a hidden-state observation.

An experimental signal is not scientific proof.

The Runtime Evidence™ ecosystem MUST disclose these distinctions wherever metrics are presented.

---

# 12. Strategic Objective

The purpose of the Metric Legitimacy Matrix is to transform Runtime Evidence™ from a collection of metrics into a system of explicitly bounded evidence claims.

The MLM ensures that Fieldglass®, EvidenceCommons®, and future Runtime Evidence™ systems remain:

* Transparent
* Challengeable
* Reproducible
* Scientifically bounded
* Epistemically honest
