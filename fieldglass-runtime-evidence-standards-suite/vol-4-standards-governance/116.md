# Abstract

The Metric Legitimacy Matrix (MLM) establishes the canonical classification framework for Runtime Evidence™ metrics.

Not all runtime metrics represent the same type of evidence claim. Some metrics are directly observable, some are deterministically derived, some operate as bounded proxy signals, and others exist as interpretive or experimental research layers.

The MLM provides a formal mechanism for disclosing:

* Evidence basis
* Certification scope
* Challengeability
* Claim boundaries
* Artifact inclusion rules

The purpose of MLM is to ensure that every Runtime Evidence™ metric explicitly communicates what it represents, how it was produced, how it may be challenged, and what it is permitted to claim.

---

# 1. Purpose

Fieldglass® does not treat all metrics as equivalent.

A metric such as:

```text
Turn Count
```

is fundamentally different from:

```text
Runtime Pressure
```

which is fundamentally different from:

```text
Emergence Dynamics
```

The Metric Legitimacy Matrix formalizes these distinctions.

---

# 2. Core Principle

Every public metric SHALL belong to a legitimacy class.

No Runtime Evidence™ metric SHALL be exposed without disclosure of:

* Evidence Class
* Challengeability
* Certification Scope
* Claim Boundary

---

# 3. Legitimacy Classes

## 3.1 Direct Evidence

### Definition

Directly parsed, counted, extracted, or located from acquired runtime evidence.

### Characteristics

* Observable
* Deterministic
* Reproducible
* Fully challengeable

### Certification

Certified

### Examples

* Turn Count
* Role Count
* Tool Failure Count
* Observable Failure
* Runtime Event Count

---

## 3.2 Derived Evidence

### Definition

Deterministically computed from direct evidence using disclosed computation rules.

### Characteristics

* Traceable
* Replayable
* Recomputable

### Certification

Certified

### Examples

* Lead-Time
* Formation Timeline
* Boundary Crossing
* Replayability
* Evidence Integrity

---

## 3.3 Proxy Signal

### Definition

Observable but heuristic indicators derived from evidence patterns.

### Characteristics

* Traceable
* Bounded
* Partially challengeable

### Certification

Certified with explicit boundaries

### Examples

* Runtime Drift
* Runtime Pressure
* Role Topology
* Containment Coupling
* Basin Pressure

---

## 3.4 Interpretive Layer

### Definition

Research interpretations built on observable runtime evidence.

### Characteristics

* Contextual
* Research-oriented
* Non-authoritative

### Certification

Preserved for review

Not certified as hidden-state truth.

### Examples

* Emergence Dynamics
* Symbolic Time
* NOESIS Evidence
* Continuity Interpretation
* Re-Entry Interpretation

---

## 3.5 Experimental

### Definition

Signals requiring additional validation, replication, or review.

### Characteristics

* Research-only
* Subject to revision
* Non-certified

### Certification

Not certified

### Examples

* Candidate observables
* Experimental indicators
* Validation studies

---

## 3.6 Governance Artifact

### Definition

Metrics describing evidence integrity, provenance, replayability, preservation status, certification state, and governance readiness.

### Characteristics

* Governance-oriented
* Preservation-oriented
* Non-behavioral

### Certification

Certified

### Examples

* Evidence Integrity
* Replayability
* Provenance Completeness
* Certification State
* Evidence Chain Status

---

# 4. Challengeability Model

Every public metric SHALL disclose challengeability.

## Challengeable

Directly challengeable through evidence inspection or deterministic recomputation.

Examples:

* Turn Count
* Lead-Time
* Evidence Integrity

## Partially Challengeable

Derived from bounded heuristics but exposes source signals.

Examples:

* Runtime Drift
* Runtime Pressure
* Role Topology

## Experimental

Requires additional validation and research review.

Examples:

* Emergence Dynamics
* Symbolic Time

## Prohibited

Metrics SHALL NOT be presented as public Runtime Evidence™ metrics if they cannot be challenged, inspected, or independently reviewed.

---

# 5. Certification Scope

Certification does not mean:

* Truthfulness
* Correctness
* Benchmark superiority
* Deployment approval
* Hidden-state access
* Consciousness detection
* Intent inference
* Root-cause certainty

Certification means:

1. Runtime evidence was acquired.
2. Runtime evidence was computed.
3. Telemetry was generated.
4. An artifact was produced.
5. Provenance metadata exists.
6. The evidence chain is replayable.
7. The artifact is preservable.

---

# 6. Certification Inclusion Rules

## Certified

* Direct Evidence
* Derived Evidence
* Bounded Proxy Signals
* Governance Artifacts

## Preserved But Not Certified

* Interpretive Layers
* Experimental Signals

# 13. Claim Boundaries

The Metric Legitimacy Matrix exists to prevent category errors.

A proxy signal is not a fact.

An interpretive layer is not a hidden-state observation.

An experimental signal is not scientific proof.

The Runtime Evidence™ ecosystem SHALL disclose these distinctions wherever metrics are presented.

# 15. Strategic Objective

The Metric Legitimacy Matrix transforms Runtime Evidence™ from a collection of metrics into a system of explicitly bounded evidence claims.

Every metric must disclose:

* what it measures,
* how it is derived,
* how it can be challenged,
* what certification applies,
* and what it is prohibited from claiming.

The objective of MLM is not to increase confidence.

The objective is to disclose evidentiary status so confidence may be independently evaluated by reviewers, operators, auditors, researchers, and future Runtime Evidence™ systems.

The MLM ensures that Runtime Evidence™ systems remain:

* Transparent
* Challengeable
* Replayable
* Reproducible
* Governance-ready
* EvidenceCommons-compatible
* Scientifically bounded
* Epistemically honest
