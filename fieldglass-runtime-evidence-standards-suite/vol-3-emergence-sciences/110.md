# Fieldglass Runtime Evidence 110: Runtime Replay and Reproducibility

## Purpose

Runtime Replay defines how a computed Fieldglass run becomes an inspectable evidence sequence. Replay is not animation. Replay is deterministic reconstruction of evidence frames, event markers, regime movement, boundary anchors, role pressure, and preservation state.

## Core Question

```txt
Can another reviewer follow the same evidence path from input to conclusion?
```

## Replay Frame Model

Each replay frame SHOULD include:

```txt
frame_id
turn_index
timestamp_or_runtime_index
role
regime_state
phi
boundary_state
temporal_state
role_state
pressure_state
evidence_events
claim_boundary
```

## Replay Identity

Replay identity MUST be bound to:

- input hash
- canonical turns hash
- telemetry hash
- instrument version
- schema version
- replay engine version

## Replay Integrity

Replay is valid when:

- raw input is preserved
- canonical turns are stable
- telemetry was computed deterministically
- event ordering is reproducible
- exported frame count matches computed evidence
- claim boundaries are attached

## Replay Challenges

A reviewer MAY challenge:

- event selection
- marker interpretation
- confidence level
- claim boundary wording
- export completeness

A challenge MUST NOT silently mutate the original case.
