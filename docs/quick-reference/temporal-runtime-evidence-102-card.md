# Fieldglass Temporal Runtime Evidence 102 Card

## Core Frame

Temporal forensics reads time as evidence.

Fieldglass does not see hidden model time. It reconstructs observable runtime time-structure from the evidence trail.

## Temporal Evidence Chain

```txt
Raw sequence
↓
Turn chronology
↓
Runtime trajectory
↓
Pressure accumulation
↓
Temporal deformation
↓
Lead-Time
↓
Failure timeline
↓
Boundary formation
↓
Replayable temporal evidence
↓
Exportable case
```

## 10-Step Temporal Reading Order

```txt
1. What is the turn range?
2. Where is the stable phase?
3. When does pressure first appear?
4. When does the trajectory begin weakening?
5. When does role/tool pressure accelerate?
6. Does the run compress into retries or repeated attempts?
7. When does the failure boundary form?
8. What is the Lead-Time?
9. Where does observable failure occur?
10. Can the timeline be replayed and exported?
```

## Monitoring vs Temporal Runtime Evidence

```txt
Monitoring asks:
Is the system healthy now?

Temporal forensics asks:
When did the run begin moving toward failure?
```

## Temporal Case Steps

```txt
1. Identify run window.
2. Locate stable phase.
3. Locate pressure formation.
4. Identify trajectory shift.
5. Inspect role/tool timing.
6. Locate failure boundary.
7. Check Lead-Time.
8. Replay the timeline.
9. Export the evidence case.
10. Attach claim boundary.
```
